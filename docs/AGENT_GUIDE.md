# Working with Aw as a folder-aware agent

Aw is a local research record and LaTeX editor, not an autonomous worker scheduler. Use this short map first, then [RESEARCH_WORKFLOW.md](RESEARCH_WORKFLOW.md) for the guarded notebook commands and execution rules. Follow `AGENTS.md` and the user's narrower request. Advice or a research question is not permission to restructure source.

## Start or resume a project

### Default: work in Aw without opening its UI

Aw remains the working harness, not just a viewer for files produced elsewhere. Keep the owning project, conversation, notebook, evidence links and request status connected through the scoped tools. Save authorized readable TeX notes alongside that project's source and link them from the owning notebook when available. Do not skip notebook storage or task completion merely to avoid visiting the app. Opening Aw and inspecting its renderer are for preparing the human's review, explicit display/UI work, or publication presentation checks—not routine exploration. Data access through CLI/files is not a visual app visit.

For ordinary source work, use the confirmed paper folder. Do not open Aw, test its server, start a launcher, walk menus or take screenshots just because the project uses Aw. Reason first; save the authorized ordinary `.tex` note in that folder. Existing registered projects list ordinary files when opened/refreshed; a new independent TeX root can be chosen in Switch manuscript. Creating a file does not switch the project-wide main file, create a notebook conversation or complete a saved task. Do not insert an input into an existing manuscript merely to catalogue a note.

Use the user's exact folder or saved scope. If identity needs checking, read only the relevant entry in Aw home's `.paperfocus/projects.json` and its returned project-data catalogue; no HTTP health check is needed for ordinary file creation. Keep Aw metadata and pending notebook artifacts outside the checkout. New, independent unmarked notes default to research notes; existing publication text, locks and saved writing rounds still require their guarded policy/review workflow. Reuse an existing notes root only when its policy and editing scope are known. Preserve concurrent source edits.

App code and Aw's research-data home can be different directories. Run tools by
their installed code path, but always pass the confirmed **data home** as
`--workspace`; never infer it from the CLI's current directory. First-copy transfer
uses `awSync.ts clone` only into a new, absent home, with preview and exact-plan
commit. It preserves IDs and source structure and never resumes pending work.
See [DEVICE_SYNC.md](DEVICE_SYNC.md) before transfer. The launcher can open that
home with `--workspace`, but agents doing offline research do not need to launch
it. Protected whole-project migration and remote compute are not implemented. With explicit data-transfer
scope, `collect` can preview then commit one existing experiment notebook through
guarded stores, with an immutable backup and resumable journal. It never changes
source/catalogue/review state, runs code or completes tasks. The separate `--entries`
mode adds selected new conversations with distinct new owners, preparing evidence
first and saving the guarded catalogue last. Existing conversations are not
rewritten; ready responses remain unreviewed and waiting work is never restarted.
Use `collect-status`
after interruption; partial writes may exist. Never copy detached JSON over stores.

For broader authorized reconciliation, `awSync.ts merge` previews a guarded batch
of ordinary research source, safe existing conversation fields and notebook evidence.
Independent literal edits combine; exact conflict IDs and scoped text decisions handle
ordinary overlaps. Publication/locked wording, ownership, review/policy/request state,
deletions and ambiguous code/output remain held. Exact-review commit keeps checkpoints,
leases and resumable journals, never executes cells or grants approval. Complete
batches join histories; partial batches retain only their local parent.
`checkpoint` remembers its parent; `.aw-sync` export/receive transfers checked history
and unique data, not live imports. Pair explicit SSH paths/identity only with the
human's chosen host/channel scope. `sync --peer HASH` previews both saved copies;
`sync --review HASH --commit` collects both only when the complete proposals agree.
`sync-status` and identical retry preserve interrupted collections. Save drafts on
both copies first; new work stops unsafe retries. No app server, model/API, job rerun,
public listener or automatic host-key acceptance is involved. See DEVICE_SYNC.md for
the full scope/budgets and the distinction between receipt, collection and agreement.

Exploration needs only a brief markup/readability check of changed passages. When the human wants a readable note, do one focused check with an already available local renderer/compiler if useful; do not launch the Aw UI/server solely for that check, install dependencies, or run a whole-document polishing ceremony. If the necessary renderer is unavailable, say what was not checked and keep the source deliverable.

Use `awResearch.ts COMMAND --offline` for discover/bind/inspect/cell/output/inputs/manifest/put/batch/organize/finish. It accesses the same validated disk stores without HTTP, a listener or an automatic server fallback. Ownership, revisions, saved tickets and human decisions still apply. Bindings retain identity, not transport: keep `--offline` when using `--scope`. With the human's compute permission, `run --offline --allow-python` runs a saved code cell in fresh Python, waits for collection and returns its new revision and immutable run path. Text, tables, plots, sweeps, heatmaps and Matplotlib figures go straight into the same notebook; no manual import or server is needed. `job --offline` reads a saved run without executing it. Shared sessions, live waiting/model jobs, preflight, evidence snapshots, phase rollover and publication/versioning tools still need their live protocols. See the research workflow's [offline Python loop](RESEARCH_WORKFLOW.md#server-independent-records-and-python).

Updated store writers use per-record cross-process locks, preserving existing outputs/metadata and rejecting stale revisions. Before mixing offline saves with an older running service, arrange one safe restart after that service's runs/drafts settle; old processes do not acquire the new locks. Offline-only work needs no service or restart. Locks wait briefly and are never stolen on a timeout. A crashed writer's `.aw-lock` requires inspection and explicit recovery, not an automatic overwrite. These locks are local-host coordination, not distributed/network-filesystem locking; direct third-party JSON writers do not participate. Keep one coordinated writer per owner.

Browser recovery has a separate quota from notebook files. New per-window recovery snapshots use a versioned, lossless encoding when smaller; legacy plain JSON remains readable and shared checkpoints remain plain JSON. On quota failure, recognized inactive window copies can also be losslessly packed in place, after checking their lease, last-save timestamp and unchanged contents; active or recently saved copies and unknown records are skipped. No draft content is discarded. This changes neither disk evidence nor notebook limits. Never clear all browser storage to silence a quota warning. If compression and exact-clean-copy compaction cannot save a recovery, keep the warning and preserve the current editor; disk saves remain independent. The banner identifies the failed storage and approximate write size without exposing contents. Use the updated frontend to reopen packed browser recoveries.

For a required live operation: One connection failure is enough; do not poll, rebuild, start/restart servers or diagnose infrastructure by default. Continue independent work. Save a uniquely named pending Markdown/TeX/notebook artifact in an already confirmed returned Aw research folder (or the human's specified output folder if no data path is known). Preserve existing records and state clearly that import/finish is pending if it was not performed. Do not fabricate completion, overwrite live notebook JSON or guess a data destination.

### When notebook or saved-task access is needed

1. Use a scoped `awResearch.ts inspect --offline` once for saved records; it verifies workspace identity without a service. Live transport also verifies service identity. Confirm intended project ID, paper root, owning root policy and conversation. Separate health/registry/document probes are only for unresolved identity or a requested diagnosis, not a compulsory startup checklist. Do not choose a project merely because its browser tab is active.
2. For a new project, **Paper & files → New / open project** can create a blank paper, import files, or register an existing folder inside Aw home. This creates/registers a project; the top-bar manuscript menu creates a second root **within** a project. These are different operations. Opening an existing folder does not move its files. Git/cloud publication is a separate explicitly authorized action.
3. Read the project document and the intended conversation. Obtain notebook ownership from `entry.experimentNotebookId ?? entry.id`. Use **Copy instructions for an assistant** or the scoped CLI below, not guessed paths.
4. Continue from saved evidence. Read changed cells and complete outputs, not just summaries. Preserve other cells, metadata, IDs, output and human notes. Do not rerun a cell to rediscover a saved answer.

```powershell
node scripts/awResearch.ts inspect --offline --url 'http://127.0.0.1:4173' --workspace 'CONFIRMED_AW_HOME' --project PROJECT_ID --entry CONVERSATION_ID
```

The research lab record belongs in the owning `.ipynb`, under Aw home's returned `awDataRoot`, outside the source checkout. Keep a few pinned summaries with the current target, assumptions, useful deduction, unresolved gap, exact cells/outputs/run IDs, inspected references and next check. Do not create a second task system or repeatedly request compute permission already explicitly granted within this scope. A CLI `--allow-python` flag alone is not human permission.

### Less setup and repeated reading

**Exploration is not a typesetting pass.** Research notes get minimal editing/rendering checks unless the human requests more: inspect the changed passage for obvious broken markup or unreadable output, fix that locally, and continue reasoning. Do not default to whole-note rewriting, full PDF builds, page-by-page appearance inspection or UI editing trials. Publication manuscripts warrant appropriately scoped review/typesetting checks. Scientific reasoning, actual experimental evidence/provenance, complete-output reads and safe saves still need their normal rigor; app implementation follows its separate regression rules.

If the human makes clear that the current version is intended to be read, that is enough to request a focused readability/rendering pass—no formal QA phrase is needed. A digest, walkthrough or note prepared for their reading should be coherent and readable, with the relevant display checked proportionately. Do not confuse this with publication status, word-by-word approval, mathematical validation, or permission for exhaustive page-by-page trials. Otherwise keep working notes lightweight.

For drafting or revising reader-facing prose, reuse the general principles in [Writing overviews and research notes in Aw](PRESENTATION_REVISION_NOTES.md). They apply across subjects and document purposes; publication review guardrails still apply separately. Manuscript prose must stand alone: never refer to chats, conversations or prompts, including saying that the reader need not have followed them. Explain the work directly. The reading preview displays literal project-local PNG/JPEG/GIF/WebP `\includegraphics` references, readable captions and simple widths without changing source. PDF figures have an open link; custom graphics macros, `\graphicspath`, SVG/EPS and exact float layout require the compiled PDF. Prefer explicit project-relative paths and check the reader's chosen view when a figure is reported broken.

The compiled manuscript PDF scrolls continuously through all included pages. Page number and Previous/Next controls are visible above the PDF for direct jumps; the current page follows scrolling. Only nearby pages render canvases, while offscreen page slots retain their layout. Double-click locates the source passage without narrowing All sections to This section; section view keeps its containing section and block-window view keeps its radius. Search, zoom and build details remain in LaTeX options. Reference/file PDF readers retain their own page controls. Check later pages before treating a floated figure as missing; focused compilation can change pagination relative to the full document.

Opening a manuscript in a visible LaTeX PDF pane restores its own current build, or automatically requests a focused compile after checking saved status. This opening behavior is separate from the optional idle-compilation preference for ongoing edits. Source conflicts and unsettled navigation stop it; failures do not retry in a loop. The current window keeps bounded metadata for up to twelve immutable focused PDFs, keyed by project/root/engine and scope and validated against the source revision. Returning to an unchanged view reuses its PDF without running TeX. On a cache miss, the service's existing dependency-checked focused-build cache can still avoid another TeX run. No PDF/draft payload is added to browser recovery storage. Late results from a root the user has left cannot replace the current preview; another root's project-wide last build is never shown as the selected manuscript.

`node scripts/awResearch.ts --help` works offline, including `inspect --help`; Node runs the client directly, with no `npx`/`tsx` download. `discover --workspace AW_HOME` lists projects, and adding `--project ID` lists only conversation identities/titles. It never changes the current project. Once the intended conversation is confirmed, `bind` with the ordinary scoped options and `--file NEW.json` creates an explicit identity file; use `--scope NEW.json` afterward. Keep bindings, edit packets and manifests in an existing folder under the returned Aw data `research/` area, not the manuscript checkout. Existing files are never overwritten. A binding checks the service workspace and notebook owner on every command; a phase's new owner needs a new binding. No binding grants compute or source-edit permission.

For related notes/code/display changes, use `batch --revision REVISION --file EDITS.json` to preview, then add `--commit` for one guarded save. Use its returned revision for the next mutation, rather than a fresh inspect after every successful save. Invalid batches and stale revisions make no partial cell changes; outputs, execution records and unknown metadata survive. Conflicts still require inspection and reconciliation; no automatic protected-write retries.

`manifest --file NEW.json` saves a hash index; `inspect --since NEW.json` identifies added/changed/removed cells, ordering changes and checked declared-input changes, without repeating unchanged context or rerunning code. This index is not a complete evidence snapshot and does not assert that the agent read or verified an output. Use `cell`/`output` for complete data. Inspect also supplies headings and exact notebook links: keep a compact current-state note pointing to the full derivations, not a claim that a short synthesis includes every proof. `job --job ID --wait-seconds 30` avoids repetitive tool turns while a bounded run completes, without queuing or rerunning it.

These client operations work with an already running older Aw service. Faster exact-cell transfer and declared-input capture are capability-gated server additions. Do not restart an occupied service to enable them. The full batch format, input limits and provenance caveats are in the research workflow below.

Filing is presentation, not storage compaction: hidden/filed cells still occupy the same notebook. If a notebook approaches its validated JSON or on-disk read limit, and the human authorizes a rollover, preserve it under its original conversation/owner and file that conversation in a readable archive folder. Start a genuinely fresh conversation/notebook for the continuing phase, with a short handoff and links to the archive. Never redirect the old entry's `experimentNotebookId`, erase outputs or move IDs silently: existing evidence URLs and run history depend on that ownership. Filed conversations load their contents only when opened, so the old notebook need not stay in the active HTML view. Preserve a fixed backup with hashes before the catalogue change. Import any external evidence with its original execution record and an explicit external/imported label; do not invent Aw run IDs. Use a focused notes root for a new research phase when requested, keeping earlier manuscripts and included files intact.

**Version your work at meaningful research transitions.** Keep ordinary progress in the current notebook; do not create a new phase for every reply. Preserve earlier claims and counterexamples rather than rewriting history when an approach changes. `inspect` reports `storage` headroom and `phase` lineage. With archival organization in scope, use `awResearch.ts phase --revision REVISION --title 'Next research phase' --file HANDOFF.md` with the same explicit workspace/project/entry options: it is a read-only plan by default. Review the plan, save browser drafts, then repeat with `--commit`. This reusable command makes a full hashed backup, files the old conversation, and creates a fresh owner with a pinned handoff and archive link, without touching manuscripts or rerunning evidence. See the workflow's rollover section for retries, recovery and snapshot-versus-phase choices.

At the top of **Notebook**, the sticky **Research phase** selector lists saved phases and archives. **← Previous phase** and **Next phase →** traverse saved lineage without opening a conversation card or archive folder. Card headers retain the same shortcuts. If a phase has several successors, choose one from **Next phase…**. Switching saves mounted notebook drafts first; a save failure leaves the current phase open. Visiting an archived predecessor keeps it filed and does not change its notebook owner, restore it into active research, or execute cells. Phase links use saved ancestry, not conversation order or manuscript version numbers. Newly created phases appear after the catalogue refreshes; preserve drafts before reloading an older open window. A frontend rebuild requires a page reload, not a service restart, to show new controls. Builds retain older hashed frontend assets so already-open editors can still load their lazy modules; these assets are app-build files, not research evidence. Never reload a dirty editor or restart an occupied service merely to deploy controls.

Opening a project normally shows the manuscript in Split + LaTeX PDF, with its newest active research phase selected for a later Notebook visit. Refresh restores the window's saved screen instead of forcing Notebook during phase hydration. A fresh explicit historical evidence link still opens Notebook and selects that requested owner; a recovery link retains its draft view. This selection happens on initial catalogue hydration/project opening only, not every poll; subsequent manual navigation is not pulled forward. It does not switch the project-wide TeX root, unfile archives, or alter experiments. The top bar starts visible; hiding it with its button affects the current session. **Advanced → Hide top bar by default** is the explicit opt-in for hidden startup chrome.

The compact priority controls distinguish **Current** (target icon: reopen the selected queued item, or the first queued item before one is selected) from **Next** (right arrow: advance to the following item, wrapping at the end). Neither action completes work. The separate checkmark handles completion/checking, and the adjacent count/chevron opens the queue. With only one queued item, Current still returns to it; Next offers suggested work if available, otherwise it is disabled.

Local Python defaults to two simultaneous runs **in different notebook owners**, always one per notebook, shared across all windows of this service. The host may set `AW_PYTHON_CONCURRENCY=1..4` at startup. Read actual capacity and active run ownership from `inspect`; `busy` alone does not mean full capacity. A busy rejection never queues code. Do not stop an unrelated run or restart the human's service to obtain a slot. See the research workflow for safe configuration and explicit execution budgets.

For longer-form explanations, derivations, literature reviews, or evolving research summaries, create or reuse an informative-notes manuscript within the project when source writing is in scope. Reuse an appropriate existing notes root rather than creating one per session. Keep it separate from the publication manuscript unless the human requests otherwise. Keep experimental code, outputs, execution records and short result summaries in the owning notebook, and link the exposition to exact cells or saved outputs. The notes manuscript is the readable research synthesis, not a replacement for the lab record; distinguish established results, numerical evidence, conjectures and unresolved gaps. Do not wait until a final paper is ready to provide this longer-form view.

## Manuscripts and included section files

The top bar's **Switch manuscript** menu lists parent LaTeX roots. Aw detects literal, braced `\input{…}` / `\include{…}` relationships, including nested/shared children, and ignores commented declarations. A parent plus its included sections is **one manuscript**. A second independent `notes.tex` or `paper.tex` is another. Shared child files are genuinely shared source: editing them can affect both roots. Detection is not a TeX macro evaluator; custom import/macros need source-editor review.

In block source editing, Backspace at the start of a nonempty block joins it to the preceding editable block in the same section/environment and source file. Unsaved visual chunks join locally; saved paragraphs use a guarded separator edit that preserves attached comment and notebook anchors. Ctrl/⌘ Z can undo a saved merge before subsequent source changes; it never overwrites later edits. A hidden/intervening block, heading command, file boundary or read-only predecessor is not skipped. Blank lines inside open `$`, `$$`, `\(...\)`, `\[...\]`, braced groups and literal environments stay inside the block until closure, including nested environments. This is literal syntax tracking, not TeX expansion or automatic repair of invalid math. The server parser and editor share the boundary rule; an older service needs a safe restart after drafts/runs settle for `paragraphEditing` support.

**New manuscript** offers a paper, informative-notes or Overview scaffold. It adds a new ordinary `.tex` root without overwriting existing files. Selection saves current source first; conflicting block drafts can be kept through the existing Source changes & drafts recovery. Raw-source save failures stop navigation. Each root retains a small reading/focus/progress snapshot and raw/source-preview preference. New conversations belong to that manuscript; legacy unscoped conversations remain project-wide until a deliberate version operation assigns their scope. Root/compiler selection is still project-wide; windows do **not** have independent compilation roots. Other windows must reopen when their root changes, preserving their drafts.

### Manuscript versions

**Overview** is a third writing purpose, distinct from Research notes and Publication draft. Treat it as a short README for collaborators: explain the aim, main idea, current status and next step in a few paragraphs or roughly a page, then point to the main manuscript and evidence for detail. Avoid dumping derivations, experiment logs or a full paper into it. A coherent first draft is allowed within source-writing scope; publication's incremental approval is not mandatory, but existing locks and human work still apply. Check readability proportionately, not exhaustive typesetting. Notes remain the default.

**New manuscript → Overview** creates a short ordinary LaTeX scaffold, linked in Aw to the previously selected manuscript. The purpose menu's **Main manuscript** selector changes this link and **Open main manuscript** follows it through the normal guarded switch. Selecting Overview on an existing root changes metadata only, never inserts text. The link is project-local; for collaborators outside Aw, put a shareable arXiv/repository/PDF URL in the overview text rather than a localhost URL. No automatic upload happens. Versions inherit the chosen link. Agent inspect reports `mainManuscript` (research) / `overviewTargets` (versions). Agents can set/remove a link with `awVersions.ts purpose ... --purpose overview --expected-purpose overview --target MAIN.tex --expected-target none` (or the exact previous target); `--target none` removes it. Preview first, then `--commit`; no source, review or notebook changes.

**Notebook → Move / copy notebook** brings one conversation or a whole notebook from any existing root to another, without switching the selected manuscript. Each conversation's ⋯ menu also offers **Move / copy to version**. Move changes catalogue affiliation and retains experiment identity. Copy creates independent saved experiment notebooks, preserving cells, outputs and metadata without running them. Original passage links remain at their real source; this is not source migration or approval. Waiting requests and active runs must finish first. Save drafts in other windows before copying their work.

Agents can use `node scripts/awVersions.ts inspect --workspace AW_HOME --project ID` for all conversation IDs and roots, then `transfer --workspace AW_HOME --project ID --root SELECTED.tex --revision SOURCE_HASH --notebook-revision NUMBER --entries ID,ID --target DESTINATION.tex --mode copy` (or `move`). Preview is default; repeat with `--commit` after checking the scope. Revision guards reject stale saves. Prepared copies are retained on a multi-store failure; inspect the reported journal before retrying. Transfer is within one project, not across unrelated paper repositories.

At each new request, read the current owning-root policy returned by `awResearch.ts inspect`, even if an older chat remembers a publication workflow. New briefs include this policy; already-running chats are not automatically interrupted or rewritten. Notes allow full authorized explanations, exploration uses minimal presentation checks, reading-ready requests get focused readability checks, and publication changes retain human review and wording locks.

**Writing purpose** in the manuscript menu distinguishes **Research notes**, **Overview** and **Publication draft** per independent TeX root. New notes scaffolds are marked notes; unmarked roots default to research notes, never by filename inference. Choosing the Paper scaffold or Publication draft explicitly enables the publication workflow. Authorized notes may be full-length first-pass explanations/derivations/digests, without the publication three-paragraph cap. Preserve human work, settled wording locks, scientific status and notebook evidence. Publication prose uses the incremental review workflow. Purpose is metadata, not source-writing permission; agents must not switch it to evade human review. Changing it preserves pending reviews and comments and does not retroactively approve a document. New versions inherit it; other open windows refresh it without changing drafts or invalidating an unchanged compiled PDF.

`awVersions.ts inspect` reports the selected purpose and root map; `awResearch.ts inspect` reports the owning conversation's manuscript and writing policy. To set an existing root only at the human's direction: `node scripts/awVersions.ts purpose --workspace AW_HOME --project ID --root MAIN.tex --revision SOURCE_HASH --expected-purpose publication --purpose notes`. This previews; repeat with `--commit` to save metadata only. Source/root and expected-purpose fences prevent stale changes. Never infer scope from a selected root in another window. **Ask for a full research note** prepares an ordinary saved conversation, not a writing-round JSON request or automatic source replacement.

**Switch manuscript → New version** saves current source, notebook notes and mounted experiment drafts, then copies the root and every supported literal `\\input{…}` / `\\include{…}` TeX dependency into new ordinary files. It does not flatten or rename originals. The menu groups a family chronologically as **v.1, v.2, …**, with creation dates and its previous-file link in the tooltip. Independent manuscripts start separate families; branching an earlier member takes the next unused family number. Switching roots also switches the visible notebook catalogue. Reading positions remain per root.

By default the notebook continues from the previous version: conversations receive new IDs and independent experiment owners, keeping notes, source, outputs, stable cell IDs and unknown metadata. Deliberately shared owners within the previous version remain shared within its new copy, never with the old version. **Advanced → Start with a fresh notebook** instead starts an empty catalogue without deleting earlier evidence. Exact uniquely matched reviewed paragraphs carry their existing human locks; ambiguous or modified text does not inherit approval. Old comments, unreviewed proposals and pending requests stay in the old version and remain in the project queue; copying is not resolving them. Completed/pending request history is retained as closed history with new turn IDs, without duplicating jobs or redirecting replies.

Figures, bibliographies and other non-TeX resources remain shared. This is an editable manuscript branch, **not an immutable project backup**. Literal inputs are rewritten to independent TeX copies, including preamble files and `includeonly`; unsupported macro/unbraced/import/subfile loaders refuse automatic copying. New roots must stay in the same folder as the old root so relative asset paths remain valid. Missing dependencies, existing targets, stale revisions and active runs in carried owners refuse the operation. No code runs, publication or dependency download occurs.

For agents, use the short offline help and explicit project scope:

```powershell
node scripts/awVersions.ts inspect --workspace AW_HOME --project PROJECT_ID --url http://127.0.0.1:4173
node scripts/awVersions.ts create --workspace AW_HOME --project PROJECT_ID --root main.tex --revision SOURCE_HASH --notebook-revision NUMBER --file main-v2.tex
# Review the read-only plan; repeat with --commit only with source/versioning permission.
# Add --fresh only when an empty notebook is wanted.
```

Inspect supplies current identity, revisions, lineage and conversation owners without changing selection. Create checks both revisions; commit returns the document, notebook, assistance store and old-to-new conversation IDs. Use these exact new identities, not old research bindings. Previous `.ipynb` run records remain with their original owner; copied notebook metadata `awVersionOrigin` records its complete original path/revision. Copies retain prior execution metadata as provenance, not newly executed results. Historical evidence URLs still point to their original owner; only exact unique source passages are relocated to the new TeX root. Stale/ambiguous captures retain their old-version links.

The operation spans source files and two guarded stores; it is recoverable, not a filesystem-wide transaction. An interrupted/stale preparation keeps new copies and an explicit `manuscript-version-UUID.json` journal in the returned Aw data folder. Inspect before retrying; do not delete preparations or force later revisions. Original TeX and notebooks are not replaced. Version creation assigns previously unscoped standalone conversations to the source root, and previously linked ones to their recorded root, so they do not silently appear in a fresh version. An empty advanced notebook still carries exact source wording locks. The new backend needs one safe restart; never restart another owner's run for deployment or QA.

**Sections & files** offers two deliberate actions:

- **Create a new section file** creates the child and adds `\input{relative/path.tex}` before the parent's `\end{document}`.
- **Move current section** moves a complete literal section, with its subsections up to the next same-or-higher heading in that source file, into a new child and replaces that span with an input. Existing referenced files remain referenced; they are not duplicated or renamed. Environments, unsupported import/subfile relocation, ambiguous input paths, stale source and existing target filenames are refused. Parent source is bounded for this structural operation; larger/unsupported cases need manual source editing.

Use **Manuscript scope → All sections / This section** to edit the assembled container or a focused subtree. Fresh manuscript views default to **All sections**; saved deliberate view choices are restored. Switching scope updates the visible LaTeX PDF automatically after safe source saves, independently of the typing-idle compilation preference. Returning to an unchanged scope reuses an exact cached PDF; late builds for a scope you have left cannot replace the current preview. Source conflicts pause the update rather than overwriting another editor's work. Aw saves each paragraph back to its originating `.tex` file. **Paper & files** opens an included file directly; **LaTeX source** permits raw commands. Never flatten all included source into the parent merely to make an edit.

**Undo section/file change** restores the exact parent and removes only the unchanged child created by that operation. Later source edits/root changes prevent automatic undo. Both the old parent and child contents are retained in **Source changes & drafts**. The immediate Undo notice is window-local and resumes on a normal tab refresh when session storage is available; dismissing it does not delete the disk recovery/journal. Exact ordered paragraph matches retain notebook return anchors where possible; uncertain old comments/task anchors are kept for review, not guessed or resolved. Previously copied URLs remain versioned and may report a changed source version after a structural edit.

### Guarded structural APIs

Only use these when source restructuring is in the user's scope. Prefer the UI for human choices. Every POST requires the actual same-origin `Origin` and JSON content type. The source revision covers **all project files**, not just the root.

| Endpoint | Request / meaning |
| --- | --- |
| `POST /api/paperfocus/projects` | `{action:"create",name,files?}` creates a project; `open` registers `{folder,name?}`; `select` opens `{projectId,mainFile?,engine?,expected?:{mainFile,revision}}`. Use the optional fence for manuscript switches. |
| `POST /api/paperfocus/files` | `{projectId,mainFile,revision,files:[{path,data}]}` adds new files with base64 bytes; never overwrites. A new manuscript is a standalone root, not a section fragment. |
| `POST /api/paperfocus/files/section` | `{projectId,mainFile,revision,file,title}` creates/includes a section; substitute `nodeId` for `title` to move a current section. Returns `document`, exact `relocations`, `operationId`, `recoveryId`, `file`, `parentFile`. |
| `POST /api/paperfocus/files/section/undo` | `{projectId,mainFile,revision,operationId}` undoes that exact operation at its returned revision. Reread and stop on conflicts; never pass a newer revision to force undo. |

Recovery copies and operation journals are in the returned project data root's `source-drafts/`, never paper-local `.paperfocus`. An interrupted operation can leave a new unreferenced child alongside an intact parent. Inspect it and the journal before retrying; do not overwrite/delete either as cleanup. Undo is not an atomic transaction across two files: a crash after parent restoration can leave an unreferenced child, whose contents remain recoverable. This is deliberately recoverable rather than a delete-original fallback.

## Two-way evidence links

**View → Copy passage link** copies a saved manuscript position after saving source. Each experiment cell's **Links** menu copies a cell link or a selected **zero-based saved output** link, or a `\href{…}{…}` LaTeX reference (`hyperref` required). For a conversation captured from a manuscript passage, the link includes a reciprocal **Return to manuscript passage**. Standalone questions do not invent a source origin: copy an explicit passage link and add it as `awBack` when creating that evidence reference. The notebook conversation's existing **Passage** control also returns to its captured source, switching roots when its recorded root is known.

Link query contract (ordinary same-app URLs, no remote upload):

- Manuscript: `awProject`, `awPanel=paper`, `awRoot`, `awRevision`, `awNode`, `awParagraph`, `awFormat=reading`.
- Evidence: `awProject`, `awPanel=notebook`, `awNotebook=CONVERSATION_ID`, `awCell=STABLE_CELL_ID`, optional `awOutput=ZERO_BASED_INDEX`, `awEvidence=NOTEBOOK_REVISION`, `awFormat=reading`.
- Reciprocal origin: `awBack=ENCODED_MANUSCRIPT_URL`, set with `URLSearchParams`, not hand concatenation. Aw accepts only the same app origin/path, same project and a manuscript destination. It rejects external, foreign-project and recursive return URLs.

For example, build an evidence URL from the exact `inspect`/`output` identities:

```javascript
const evidence = new URL("http://127.0.0.1:4173/");
for (const [key, value] of Object.entries({ awProject: projectId, awPanel: "notebook", awNotebook: conversationId,
  awCell: cellId, awOutput: "0", awEvidence: notebookRevision, awFormat: "reading", awBack: passageUrl })) {
  evidence.searchParams.set(key, value);
}
```

A deep link opens folded, suppressed, filed or trashed evidence **for inspection**, without changing its catalogue flags or running Python. Missing cells/outputs and changed notebook revisions are reported. These are live saved-evidence references, **not immutable citations**; use `evidence --revision …` for a fixed snapshot with hashes. An output index identifies its saved slot, not an eternal experiment: rerunning can change that slot. Source links do not guess a paragraph at a different revision or root. An explicit link to a known manuscript root opens it through guarded save-before-switch navigation, with project-wide root selection. Unsettled source drafts, raw editing or recovery windows retain **Open linked manuscript** instead; stale locations need review. Fresh manuscript views default to Split + LaTeX PDF with implicit, box-free source blocks, not explicit boxes or the full-file raw editor. Saved view preferences and explicit reading/preview links still take precedence. Loopback links are local to this Aw service/device, not suitable as public-paper URLs.

### Handle comments during a revision pass

The block-comment view has **Next comment outside this block →**. It leaves the block filter and opens the next unresolved comment in priority order, wrapping if needed and skipping resolved/hidden comments. It remains available after resolving the block's last comment; if no other comments remain, it is disabled. Navigation never resolves a comment. **Show all comments** still opens the wider list without selecting another item.

Text can be drag-selected and copied in both Rendered text and LaTeX PDF previews. PDFs use a selectable text layer aligned to the displayed page, including zoomed and rotated pages; links and double-click source navigation remain available. Selected continuous-PDF pages stay mounted while scrolled out of view. This is ordinary browser selection, not a saved highlight, comment or source edit. Image-only/scanned pages without embedded text are not OCRed, and complex mathematical copy follows the PDF's embedded text encoding.

Annotated source blocks have a persistent comment-bubble/count at their right edge. It appears only while unresolved comments are attached to that safely located block. Clicking it opens **Comments on this block**, with a selectable list of its comments and **Show all comments** to return to the wider review. Section-heading annotations have the same saved-comment indicator, distinct from the hover/focus icon that creates a new comment. Resolving the last attached comment removes the indicator; quotes and resolved history remain saved.

**Reply → Save reply** appends a linked comment without changing the parent's wording, saved quote or resolution. Replies can themselves receive replies. **Original comment →** returns to the parent, and its **Replies** list opens children, including resolved ones. Explicit **Resolve** closes the selected comment and all existing descendant replies, including set-aside replies, preserving quotes, snapshots and history. It never closes ancestors, siblings or unrelated comments. **Reopen** affects only the selected comment. Replying to an already resolved comment still queues the new reply without reopening its parent; resolving that parent again also closes the new reply. Agents must check the entire affected thread before resolving a parent; reply contents may still contain unresolved concerns. After resolution, navigation skips the replies closed with the parent.

Agents may resolve simple, fully addressed comments after checking the saved manuscript. Leave substantive claims, uncertain interpretations, partial fixes and choices worth human assessment open. Add an anchored assistant reply describing a non-obvious attempt, a disagreement or the remaining question; use a new comment for a separate concern. Preserve the original quote and snapshot, and report the resolved and still-open IDs in a short handoff. Resolving a comment is not approving publication text or unlocking wording. A dedicated comment-only review packet remains read-only unless the human separately changes its scope.

In the comment detail panel, **Jump to commented text** opens the comment's saved manuscript automatically, then closes the detail inspector, reveals the normal source/preview layout and aligns both panes to the passage, without resolving the comment or narrowing All sections. Cross-project queue navigation saves the current source and waits for its guarded notebook/assistance saves before loading the owning project; passage lookup uses that project's real saved task, never a foreign queue summary. Root switches use the same guarded save-before-switch operation as Switch manuscript. Failed saves stop navigation. A stale PDF is saved/rebuilt safely before using its source map, with unchanged focus builds reused from cache. Reopen the saved comment from the queue or History. An edited paragraph can still be located by a unique explicit `paperfocus:paragraph=ID` marker in the same file/root, or by its confirmed current disk block during unsaved typing. The panel identifies this as a changed block, preserves the original quote and keeps exact-range Ask/Rephrase disabled. Position-generated IDs alone never justify relocation after file edits. Missing or ambiguous passages are not guessed; an unavailable saved root/project leaves the quote and history intact.

Browsing comments preserves the manuscript scope. A narrowed source view has a visible **Show all sections · Exit focused view** button beside its scope selector. **Resolve** in the detail panel immediately selects the next open comment in priority order outside the resolved thread, or the previous one if it was last. With no comments left the panel shows that result. This does not resolve the newly selected comment. **Priority queue → Resolve all comments…** confirms the number of queued comments in the current project across all queue pages, plus their descendant replies (including set-aside replies). It does not touch other projects, unrelated set-aside comments, research requests or wording proposals. Resolved comments retain quotes/replies in History and can be reopened. An agent must not use this bulk action as a substitute for checking individual fixes.

Use the existing review helpers and guarded assistance store: `makeReviewComment` in `src/review.ts` captures an exact current selection; mark agent-authored additions as `author: "assistant"` and use `replyTo` for the original comment ID. `resolveReviewComment` resolves the specified issue and its descendant replies while preserving history; reopening affects only that issue. Read the current workbench revision and save through its revision-guarded store/API; never replace `workbench.json` directly or force a stale save. If the current passage or completion cannot be verified, leave the comment open and explain why. Comment-only JSON imports cannot resolve comments and should not be expanded with unsupported status fields.

While a comment detail is open, the block source editor keeps its verified quoted text highlighted even when focus moves to the comment field. This is a display-only annotation, separate from the native text selection and its action bar; it does not change source, clipboard contents or comment status. Closing details clears it, and selecting another comment moves it. Changed or ambiguous quotes are not guessed. Selection actions appear below the current selection endpoint after the pointer is released, bounded by the source pane.

Heading and environment-command editors have a compact comment icon that appears on hover or keyboard focus, without a permanent bar beneath the heading. Touch devices retain the icon. Select text within the command, then click it, or click with no selection to quote the command. Pending source is saved first. These comments capture the literal command and its own location, not the first paragraph beneath it. Jump verifies an exact unique command in the same source file and aligns the preview to its first paragraph when available. Renamed, changed or ambiguous commands retain their saved quotes without a guessed destination. Heading comments support note editing, Resolve/Reopen and Jump; paragraph-only Ask/Rephrase stays disabled for command targets.

**Show in preview** is a visible manuscript-toolbar action for the current source passage; highlighted text and individual block controls offer it too. It opens Split and safely saves source before using a current/cached PDF source map or the rendered-text anchor. A failed save/build leaves diagnostics instead of guessing a PDF position. Inverse navigation from an outdated PDF still asks for a current build. Double-clicking the PDF or rendered passage scrolls to source and flashes that passage for about 650 milliseconds without changing its text, selection or manuscript scope. Rebuilding a PDF in the same manuscript/scope retains its page and within-page reading offset; a different root/scope does not borrow that position. Pagination changes can shift the surrounding text, so the retained page/offset is a reading-position fallback, not an exact semantic relocation after arbitrary rewrites.

For app implementation, preserve user work, add a direct regression, follow the full checkpoint rules in `AGENTS.md`, and trial editing only on a separate origin/workspace. Backend features need one safe Aw restart after drafts/runs settle; a browser refresh alone does not reload the backend. Do not restart the user's service merely for QA.

### Browser recovery capacity

Shared recovery copies now use IndexedDB when available, rather than Web Storage's small per-origin quota. Aw waits for its recovery mirror before opening the editor, keeps existing Web Storage copies as read fallback, and never clears them merely to obtain space. Immediate tab-local copies still use session storage. Cross-window recovery updates and ownership leases are synchronized; failed transactions retain pending bytes and display a warning until retried successfully. The recovery chooser reads both the larger store and old copies. If IndexedDB or cross-window messaging is unavailable, the original bounded cache and diagnostics remain available.

This increases shared recovery capacity, not a fixed guaranteed allocation. Browser-managed IndexedDB quotas, eviction and available disk space still apply. No persistence permission is requested automatically. The manuscript, notebook and assistance stores remain independent authoritative disk records. A session-cache warning is a separate issue from shared-cache capacity. Save pending work before reloading into new client code, and never discard a browser recovery to silence a warning.
